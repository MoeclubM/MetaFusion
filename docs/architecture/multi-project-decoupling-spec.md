# 多项目解耦方案（历史提案摘要）

> **历史资料，非当前契约。** 本文摘要保留 2026-09 初期拆分方案及其与落地结果的差异。当前路由、数据归属、认证与迁移职责以[子系统拆分与迁移基准](./service-split-migration.md)为准；数据权限见[数据库角色与最小权限](./database-roles.md)，部署操作见[切流手册](./cutover-runbook.md)。

## 原方案与实际差异

| 主题 | 原方案 | 实际落地 |
| --- | --- | --- |
| 仓库 | 目录、账号、互动、存储、网关、文档分别建仓 | 账号、互动、存储、文档独立仓库；目录、前端、编排及生效网关保留在主仓；旧网关仓仅保留检查脚本 |
| 数据 | 各服务独立 schema 或数据库 | 当前共用 PostgreSQL 实例，各服务使用自有 schema；不建跨 schema 外键，不跨域 JOIN |
| URL | 按服务划分独立路径命名空间 | 统一使用 `/api` 命名空间，由主仓 `deploy/nginx.conf` 按路由分流 |
| 身份 | 账号中心签发令牌，各服务本地验签 | 保留；令牌与权限细节以子系统契约及账号服务实现为准 |
| 网关 | 独立的 `metafusion-api-gateway` 运行仓库 | 生效的 Nginx 配置在主仓；外层 TLS 终止按部署环境配置 |

旧版仓库创建、PR/Issue 命令和阶段路线已省略；当前操作流程见各仓库规则。
