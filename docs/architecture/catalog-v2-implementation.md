# v2 实现与模块边界

面向编目者的模型、例子与端点见 [编目教程](../../docs-site/docs/catalog.md)。

核心位于 `backend/internal/catalogv2`：统一实体注册表、类型专用结构表、动态定义、独立身份会话、修订与 outbox。所有核心写事务共用 advisory lock，乐观版本避免静默覆盖；复合外键和延迟触发器拒绝跨域父子和循环。该首版串行化核心写入，适合中小规模协作站；高写入量时需要按受影响图范围缩小锁粒度。

`cmd/server/catalog_v2.go` 负责装配：默认 v2，`METAFUSION_MODE=legacy` 显式启动旧系统。核心不初始化旧 config、Redis、S3 或 OpenSearch。外围初始化失败只影响能力接口和外围路由，目录仍可启动。

`moduleapi` 为稳定 DTO 接口，`moduledeps` 为独立 Semver/DAG 库。模块表没有指向核心表的外键，模块只能通过 Catalog 接口查询实体和提交提案。合并事件包含旧 ID 和目标 ID；outbox 与修订同事务，消费采用至少一次投递和事件 ID 去重。个人记录冲突保留旧记录，目标已有评分不会被后台事件覆盖。

媒体处理使用独立 `media.jobs` 队列，租约允许中断恢复。处理失败只写任务状态，不修改元数据。进程中只有模块启用时才领取任务；已领取任务可能在停用前完成。首版模块启停不等于代码热加载。

前端 `/catalog` 使用独立 CatalogProvider，根布局不挂载 v1 AuthProvider 或全局播放器。资源、社区与个人记录组件动态导入，先检查能力再请求自己的 API。外部图片以带来源的核心引用保存，文件模块关闭不影响封面。

部署使用 `docker-compose.metadata.yml`。不要对现有数据执行旧导入脚本或删除卷来“适配”模型；历史数据迁移需要单独定义身份匹配和来源映射。线上升级应保留旧代码版本、数据库和卷，验证新 API、网页以及无外围依赖的目录读写后再结束维护。

尚未移植到 v2 的专用 OpenSearch、AI、通知和第三方导入器必须通过 moduleapi 新增实现，不应宣称旧插件已兼容。社区首版为条目讨论，旧论坛的私信与板块等完整能力仍在 legacy 运行模式。
