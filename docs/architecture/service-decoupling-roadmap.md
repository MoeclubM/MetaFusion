# 服务解耦状态与整改路线

本文维护当前拆分状态和未完成项，替代 2026-09-16 的审计过程、重复证据表及已结束批次流水。复核日期：2026-10-03。数据归属、路由和迁移契约只维护于[拆分契约](./service-split-migration.md)，媒体建模和前端样本见[媒体编目与前端复核](./media-catalog.md)，实例版本与备份只记 docs-local。

## 1. 当前边界

目录核心共用数据库一体化运行；账号、互动和存储以独立进程及自有 schema 解耦。服务间通过 HTTP 查询目录身份与可见性，禁止跨服务 JOIN。拆分的验收是权限、故障和发布边界，而不是仓库数量。

| 已实现 | 权威入口与检查 |
| --- | --- |
| 八种实体、结构侧表与动态定义 | [架构基准](./spec-driven-requirements.md)、[核心实现](./catalog-core-implementation.md) |
| 签发与验签分离 | 拆分契约 §4；Compose 业务容器凭据隔离检查 |
| 每服务库角色与共享审计边界 | [数据库角色](./database-roles.md)、统一授权 SQL 和越权断言 |
| 网关矩阵单源、按前缀分流及标记头验收 | `deploy/nginx.conf`、`scripts/check_gateway_matrix.py`、网关仓 `cutover-check.sh` |
| 权限码与 kind 生成物一致性 | 各仓契约生成检查和跨仓 CI |
| 发布组合、迁移器同源及摘要部署 | `deploy/versions.lock`、发布清单校验及 `deploy.sh pull` |
| 独立管理台与账号自助应用 | 三个服务的 `admin/`、账号 `user/`，由网关按路径聚合 |

已通过测试的源码能力不等于所有实例已执行迁移或同步定义；升级以对应发布清单和目标实例回读为准。

## 2. 密钥与身份边界

只有 auth 持有签发私钥，目录、互动、存储持公钥或访问 JWKS。现行令牌、PAT 内省、issuer/audience 和权限语义见拆分契约 §4；本页不再维护第二份认证协议或旧私钥兼容兜底说明。

后续协议层接入必须覆盖现有 Cookie/PAT/JWT、JWKS 失败、空权限和过期行为；不能为了复用库改变权限判定或引入签发密钥。

## 3. 协议层复用

已确认轻量 `metafusion-sdk` 方向，本机有协议骨架；当前服务尚未统一依赖该 SDK。权限码、kind 和 OpenAPI 的一致性已有生成与检查机制，不能把 SDK 骨架等同于双端接入。

只抽取稳定的身份声明、验签、错误体、分页和请求标记协议；业务模型、SQL、可见性规则继续归服务所有。接入前比较各服务实际分页语义，按版本依赖引入，先跑等价行为回归再删旧实现。不以新建共享仓库替代契约验证。

## 4. 数据层边界

统一授权的唯一来源是 `deploy/sql/roles-least-privilege.sql`，验证是 `deploy/sql/verify-role-isolation.sql`。旧社区和存储角色样例已删除；角色、审计例外、对象归属、升级和回滚步骤见[数据库角色](./database-roles.md)。

### 4.1 尚未统一的迁移职责

目录 HTTP 启动只检查兼容性，迁移与种子由 `mf-migrate` 显式执行。账号、互动和存储启动仍执行自身 DDL/未记账迁移。后续应将 owner 迁移与运行角色检查分离；迁移锁、共享审计对象归属及新表授权须一并验收，不能先撤运行角色权限再假设旧启动路径可用。

独立数据库是后续选择，当前每服务库角色已形成权限边界；不为了独立库复制目录身份或建立跨库 SQL 依赖。

## 5. 调用链与事件契约

capabilities 仅声明部署态，目录不反向探活外围服务，语义见[能力清单](./capabilities.md)。community/storage 的实体可见性仍依赖同步目录查询，超时或不可用时必须明确失败，不能默认公开或无限重试。

OpenSearch 消费目录 outbox；当前没有跨业务服务的广播消费者，实体合并后的外围收敛依赖同步查询。若引入业务事件投递，须先确定投递或拉取、重试/死信/可观测性、event_id 幂等及 merged 重定向处理，不能只加消费者注释。现有事件写入契约见拆分契约 §3。

## 6. 网关与部署编排

当前唯一生效矩阵在主仓 `deploy/nginx.conf`，网关仓负责验收脚本。矩阵归属无需复制文件维持；若将其迁往网关仓，必须一次切换权威来源、固定版本输入并保留矩阵/文档双向检查。

主仓后端、迁移器和前端有 GHCR 发布物；兄弟服务和自带 UI 由 `deploy.sh pull` 从锁定检出构建。后续独立镜像发布须扩展发布清单、同 SHA 检查及回滚组合，不能使用 latest 或复用不明旧镜像。

部署前后的配置校验、备份、显式迁移/种子、网关切换与回滚只维护于[部署与恢复手册](./deployment-runbook.md)。

## 7. UI 归属

三个服务管理台和账号登录/初始化应用已独立部署；账号与开发者普通页面仍有部分在主站，社区/资源区块仍位于目录详情页。独立管理台不等于所有用户页已拆完。

### 7.1 已确认的方向与实施条件

各服务拥有自身 UI，通过同域路径聚合。优先共享稳定设计令牌、四语字典、会话客户端和导航协议，再按实际发布需求逐域迁页。目录详情的外围区块需要明确 locale、身份、entity_id、能力与失败隔离契约，不能通过复制 shell/业务状态或微前端运行时掩盖耦合。

## 8. 剩余路线

| 批次 | 已完成部分 | 仍需验收的部分 |
| --- | --- | --- |
| B0/B1 文档与契约 | 权威入口、生成物及跨仓检查 | 随接口变化只同步直接受影响契约 |
| B2 身份与协议 | 私钥收口、声明式能力、SDK 骨架 | SDK 行为等价接入和版本发布 |
| B3 网关与发布 | 矩阵单源、标记探针、摘要发布清单 | 按需要迁矩阵来源、兄弟服务独立镜像与同组合回滚 |
| B4 数据边界 | 独立运行角色、统一授权和越权断言 | 子系统 owner 迁移/只读启动检查、共享 DDL 归属 |
| B5/B6 UI | 独立管理台及账号自助入口 | 共享稳定协议、其余普通用户页及外围区块故障隔离 |

每批先确认现有行为与真实收益，再做内聚变更；接口/数据切换须有验证过的发布组合及回退路径。转码、媒体分析、消息队列和独立数据库都不因这份路线而自动成为已实现能力。

## 9. 推荐实施顺序

| 优先级 | 交付目标 | 验收条件 |
| --- | --- | --- |
| P0 发布与恢复 | 为账号、互动、存储提供显式 owner 迁移命令、只读启动检查和固定摘要发布物 | 空库安装、存量升级、受限角色启动、失败回退与恢复演练均通过，再撤销运行角色 DDL；组合清单锁定全部服务版本 |
| P1 定义治理 | 将现有影响检查纳入草稿、预检、发布流程，补完整版本历史，覆盖字段、词表、关系规则与模板 | 缩小约束时展示冲突实体/边并拒绝直接发布；ETag 并发冲突可处理；旧事实不因定义停用而丢失。回退前重新验证数据，不能直接恢复旧配置 |
| P1 编目与编辑 | 完成跨层级的连续建档、来源复用、草稿恢复与冲突差异处理 | 用多版本 CD+BD、跨专辑歌曲、小说章节和 WEB-DL/BD 各走通保存、回读、修改及比较；不造空层级或复制同一录音 |
| P1 数据质量 | 导入预览展示来源差异和疑似重复，质量任务可解释、可修订 | 标题相近只生成候选；外部 ID、归属与来源决定人工合并；补录保留已有证据、修订与重定向；失败批次可幂等恢复 |
| P2 容量与交互 | 建立详情、比较、大目录和身份解析的延迟/请求量基线 | 先测真实目录的分页、批量读取和查询计划，再决定缓存或虚拟列表；故障、限流与空数据分别显示；身份变化清除私有缓存 |
| P2 协议复用 | 按等价行为接入 SDK 与共享 UI 协议 | 每接入一个服务就验证认证、错误、分页与超时语义，再退役对应旧实现；有版本依赖与回退组合，不先维护两份长期副本 |

新增结构边、跨服务事件、物理分库或转码应由真实样本、积压、恢复窗口与资源需求触发。优先补齐上述用户流程和运维边界；八实体核心及现有专用外键保持唯一事实来源。
