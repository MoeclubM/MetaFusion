# 浏览器仿真（多人编辑）

用真实浏览器、只走界面操作，模拟多个「真人」编辑者：新建实体、修改实体、建立关系。
用于验证前端逻辑与后台配置在真实使用下的完整性（不做任何直接 API 写入）。

## 为什么放在这里

驱动脚本需要跨机器复用（本机跑不动 10 个浏览器，服务器延迟低得多），所以进仓库而不是留在临时目录；
**凭据一律走环境变量**，不写进仓库。

## 用法

```sh
export MF_BASE=https://findverse.cc          # 目标实例
export MF_USER_PASS='<用户口令>'              # 由管理员在本地记录，不进仓库
node sim.mjs <账号数> <每人操作数> [起始编号] [波次名]
```

- 并发由 `MF_CONCURRENCY` 控制（默认 2；本机建议 ≤3，服务器可更高）。
- 日志：`run-<波次名>-simNN.jsonl`，每行一次操作（含 status 与失败原因），统计 `"status":200` 的条数即成功次数。
- **同一时间只跑一个波次**：并行多个波次会互相拖慢并写乱日志。

## 已踩过的坑（改脚本前先读）

1. **证据区不能靠 `textarea.first()` 定位**：页面「多语言题名与别名」区还有简介/别名两个 textarea，
   抢到别名框会让修改说明落错地方，客户端校验直接拦下提交（**连请求都不发**，极易误判成服务端问题）。
   现在按 `fieldset:has-text("编辑说明与来源")` 语义定位。
2. **有必填父级的层级不能单独建**：`content_unit`/`expression` 需要 `work_id`、`medium` 需要 `release_id`、
   `track` 需要 `medium_id`（服务端返回 `parent_required`）。仿真只建可独立存在的层级。
3. **并发过高会拖挂浏览器所在机器的网络**（本机 10 个 Chrome 时出现 `ERR_NETWORK_IO_SUSPENDED`）。
4. 保存按钮用文案定位（`button:has-text("保存")`）比 `button[type=submit]` 稳。
